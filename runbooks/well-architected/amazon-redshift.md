# Amazon Redshift

[Amazon Redshift](https://aws.amazon.com/redshift/)  is a fast, fully managed cloud data warehouse that makes it simple and cost-effective to analyze all your data using standard SQL and your existing Business Intelligence (BI) tools. It allows you to run complex analytic queries against terabytes to petabytes of structured data, using sophisticated query optimization, columnar storage on high-performance storage, and massively parallel query execution.

[

#### Tip #1: Leverage Pause / Resume

](#tip-1:-leverage-pause-resume)

Pausing a cluster suspends compute and retains the underlying data structures and data so you can resume the cluster at a later point in time. When the cluster is paused, the data warehouse’s storage incurs charges. On-demand compute billing is suspended and resumed on a per-second basis.

You can also automate the pause and resume actions by using a schedule that matches your operational needs.

*   [Lower your costs with the new pause and resume actions on Amazon Redshift](https://aws.amazon.com/blogs/big-data/lower-your-costs-with-the-new-pause-and-resume-actions-on-amazon-redshift/) 

[

#### Tip #2: Consider migrating to RA3 node types

](#tip-2:-consider-migrating-to-ra3-node-types)

[Amazon Redshift introduces RA3 nodes](https://aws.amazon.com/about-aws/whats-new/2019/12/amazon-redshift-announces-ra3-nodes-managed-storage/)  nodes enable you to scale and pay for compute and storage independently allowing you to size your cluster based only on your compute needs. Now you can analyze even more data cost-effectively.

They come with additional benefits such as [cross-databases queries](https://aws.amazon.com/about-aws/whats-new/2020/10/announcing-cross-database-queries-for-amazon-redshift-preview/)  today in preview.

If the smallest RA3 instance type is too big for you, do not hesitate to reach out to your account team.

[

#### Tip #3: Use elastic resize to change the node type, number of nodes, or both

](#tip-3:-use-elastic-resize-to-change-the-node-type-number-of-nodes-or-both)

The blog post [Scale your Amazon Redshift clusters up and down in minutes to get the performance you need, when you need it](https://aws.amazon.com/blogs/big-data/scale-your-amazon-redshift-clusters-up-and-down-in-minutes-to-get-the-performance-you-need-when-you-need-it/)  introduces this new Redshift capability.

[

#### Tip #4: Move cold data to S3 and query using Redshift Spectrum

](#tip-4:-move-cold-data-to-s3-and-query-using-redshift-spectrum)

The blog post [Extend your Amazon Redshift Data Warehouse to your Data Lake](https://aws.amazon.com/blogs/big-data/extend-your-amazon-redshift-data-warehouse-to-your-data-lake/)  will help you achieving that goal.

#### Tip #5: Consider 1 year / 3 years reservation options

](#tip-5:-consider-1-year-3-years-reservation-options)

As depicted in the [introduction](/workshops/f238037c-8f0b-446e-9c15-ebcc4908901a/en-US/001-intro/002-basic-activities/003-pricing-model) you can [purchase Amazon Redshift reserved nodes](https://docs.aws.amazon.com/redshift/latest/mgmt/purchase-reserved-node-instance.html)  to optimize your costs.

[

#### Tip #6: Work with Amazon Redshift Advisor

](#tip-6:-work-with-amazon-redshift-advisor)

[Amazon Redshift Advisor](https://docs.aws.amazon.com/redshift/latest/dg/advisor.html)  offers recommendations about how to optimize your Amazon Redshift cluster to increase performance and save on operating costs. It provides explanations and recommendations directly in the [Redshift console](https://console.aws.amazon.com/redshift/)  and choose `ADVISOR` in the navigation menu.

You'll get recommendations on table data compression, S3 `COPY` optimization, workload management (WLM), table statistics, and others.
