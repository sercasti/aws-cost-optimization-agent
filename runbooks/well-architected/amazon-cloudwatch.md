# Amazon CloudWatch

[Amazon CloudWatch](https://aws.amazon.com/cloudwatch/)  is a monitoring and observability service built for DevOps engineers, developers, site reliability engineers (SREs), and IT managers. CloudWatch provides you with data and actionable insights to monitor your applications, respond to system-wide performance changes, optimize resource utilization, and get a unified view of operational health.

[

#### Tip #1: Configure a retention period for all log groups

](#tip-1:-configure-a-retention-period-for-all-log-groups)

By default, logs are kept indefinitely in Amazon CloudWatch and never expire.

You can adjust the retention policy for each log group, keeping the indefinite retention, or choosing a retention period between 10 years and one day.

![CloudWatch retention](https://static.us-east-1.prod.workshops.aws/public/8844589c-f6be-4752-bd27-0dad323d1eb9/static/images/002_services/004_management_governance/001_cloudwatch/cw_retention.png?classes=shadow)

You can leverage a project such as [Log minder](https://pypi.org/project/aws-cloudwatch-log-minder/)  to automatize this either for "curative" purpose or to deploy automated retention policy assignment.

[

#### Tip #2: Check costs for log ingestion

](#tip-2:-check-costs-for-log-ingestion)

Data ingestion of logs is billed per GB. In production environment avoid send unwanted data to cloudwatch. This will incur unwanted charges.

For example, if you log entire events and keep debugging information in the `console.{log|info}` of a lambda function, every time the lambda function is called in production, this unwanted information will add to your monthly charges.

[

#### Tip #3: Delete unnecessary/unused alarms and dashboards

](#tip-3:-delete-unnecessaryunused-alarms-and-dashboards)

When you exceed ten Amazon CloudWatch alarms (Exception [High-resolution alarms](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/AlarmThatSendsEmail.html#high-resolution-alarms)  always incur charges) or when you exceed three dashboards (with up to 50 metrics) charges [incur](https://aws.amazon.com/cloudwatch/pricing/) .

To reduce costs [remove unnecessary or unused alarms and dashboards](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/add_remove_alarm_dashboard.html) .

Calls to dashboard-related APIs through the AWS CLI or an SDK also incur charges after requests exceed one million. (Exception: `GetMetricWidgetImage` always incurs charges).

[

#### Tip #4: Do not use log insights query with auto refreshed dashboard

](#tip-4:-do-not-use-log-insights-query-with-auto-refreshed-dashboard)

If you set [auto-refresh](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/change_dashboard_refresh_interval.html)  in a Dashboard with Log insights queries you will pay every time the dashboard refresh.

[

#### Tip #5: Identify unnecessary custom metrics

](#tip-5:-identify-unnecessary-custom-metrics)

When you monitor more than ten custom metrics, [additional charge incur](https://aws.amazon.com/cloudwatch/pricing/) . Custom metrics include those that you’ve created, as well as those used by tools such as the [Amazon CloudWatch agent](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/Install-CloudWatch-Agent.html) .

The `PutMetricData` API calls for a custom metric can also incur [charges](https://aws.amazon.com/cloudwatch/pricing/) .

[Amazon Kinesis Data Streams enhanced (shard-level) metrics](https://docs.aws.amazon.com/streams/latest/dev/monitoring-with-cloudwatch.html#kinesis-metrics)  and [AWS Elastic Beanstalk enhanced health reporting metrics](https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/health-enhanced-cloudwatch.html#health-enhanced-cloudwatch-metrics)  incur charges.

To reduce costs, [disable monitoring of custom metrics](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/publishingMetrics.html) , as appropriate.

You can list your metrics with the following command line (here for the `us-east-1` region).

    1
    aws cloudwatch list-metrics --region us-east-1 --output json --query 'Metrics[?!(starts_with(Namespace,`AWS`))].{Namespace\:Namespace,MetricName\:MetricName}'

It lists all metrics that don't belong to an `AWS*` namespace.

[

#### Tip #6: Check your usage of metric API calls

](#tip-6:-check-your-usage-of-metric-api-calls)

`GetMetricStatistics` and `ListMetrics` Amazon CloudWatch metric API calls that exceed one million requests incur [charges](https://aws.amazon.com/cloudwatch/pricing/) . `PutMetricData` calls, as well as any `ListMetrics` calls through the AWS Command Line Interface (AWS CLI) or an SDK, incur charges.

3rd party tools that provide aggregated views of your infrastructure may leverage these APIs and therefore may increase your Amazon CloudWatch costs. Ex: [Datadog](https://docs.datadoghq.com/integrations/faq/aws-integration-and-cloudwatch-faq/) .

To reduce costs, when possible, prefer making your [`ListMetrics`](https://docs.aws.amazon.com/AmazonCloudWatch/latest/APIReference/API_ListMetrics.html)  through the console for free rather than making them through the AWS CLI. Collect multiple [`PutMetricData`](https://docs.aws.amazon.com/AmazonCloudWatch/latest/APIReference/API_PutMetricData.html)  requests into one [`StatisticSet`](https://docs.aws.amazon.com/AmazonCloudWatch/latest/APIReference/API_StatisticSet.html)  call. For best practices when using `GetMetricStatistics` or `GetMetricData` APIs, see [Should I use GetMetricData or GetMetricStatistics for CloudWatch metrics?](https://aws.amazon.com/premiumsupport/knowledge-center/cloudwatch-getmetricdata-api/) .

[

#### Tip #7: Search log insight with a limited timeframe

](#tip-7:-search-log-insight-with-a-limited-timeframe)

[Amazon CloudWatch Logs Insights](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/AnalyzingLogData.html)  enables you to interactively search and analyze your log data in Amazon CloudWatch Logs. You can perform queries to help you more efficiently and effectively respond to operational issues.

You [pay](https://aws.amazon.com/cloudwatch/pricing/)  Amazon CloudWatch Logs Insights use per data read.

You should then search your logs using timestamp filter to prevent the read of unnecessary data.

![CloudWatch retention](https://static.us-east-1.prod.workshops.aws/public/8844589c-f6be-4752-bd27-0dad323d1eb9/static/images/002_services/004_management_governance/001_cloudwatch/cw_timeframe.png?classes=shadow)

[

#### Tip #8: Detailed monitoring

](#tip-8:-detailed-monitoring)

Amazon CloudWatch detailed monitoring for Amazon EC2 instances, Auto Scaling group launch configurations, and API gateways incurs additional charges. See Metrics in Paid tier of Amazon CloudWatch [pricing](https://aws.amazon.com/cloudwatch/pricing/)  for more details.

To reduce costs, you can disable detailed monitoring of [Amazon EC2 instances](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/using-cloudwatch-new.html#disable-detailed-monitoring) , [Amazon EC2 Auto Scaling group launch configurations](https://docs.aws.amazon.com/autoscaling/ec2/userguide/as-instance-monitoring.html#enable-as-instance-metrics) , and [Amazon API gateways](https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-config.html)  when it is appropriate.

[

#### Tip #9: Events

](#tip-9:-events)

Charges are based on the number of custom events (not the number of rules). [Events sent from one AWS account to another](https://docs.aws.amazon.com/AmazonCloudWatch/latest/events/CloudWatchEvents-CrossAccountEventDelivery.html)  are billed to the sender account as custom events.

Minimize `PutEvents` calls to further reduce costs.
