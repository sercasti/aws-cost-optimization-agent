# Amazon RDS

[Amazon Relational Database Service (Amazon RDS)](https://aws.amazon.com/rds/)  makes it easy to set up, operate, and scale a relational database in the cloud. It provides cost-efficient and resizable capacity while automating time-consuming administration tasks such as hardware provisioning, database setup, patching and backups.

[

#### Tip #1: Enable RDS Storage Auto Scaling instead of over-provisioning storage capacity

](#tip-1:-enable-rds-storage-auto-scaling-instead-of-over-provisioning-storage-capacity)

Amazon RDS for MariaDB, Amazon RDS for MySQL, Amazon RDS for PostgreSQL, Amazon RDS for SQL Server and Amazon RDS for Oracle support RDS Storage Auto Scaling. RDS Storage Auto Scaling automatically scales storage capacity in response to growing database workloads, with zero downtime.

*   [Amazon RDS now supports Storage Auto Scaling](https://aws.amazon.com/about-aws/whats-new/2019/06/rds-storage-auto-scaling) 
*   [Working with Storage for Amazon RDS DB Instances](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_PIOPS.StorageTypes.html) 

[

#### Tip #2: Monitor Database usage for right sizing instances

](#tip-2:-monitor-database-usage-for-right-sizing-instances)

You can scale your database instances by adjusting memory or compute power up or down as performance and capacity requirements change.

*   [Right Size Your Database Instances](https://docs.aws.amazon.com/whitepapers/latest/cost-optimization-right-sizing/tips-for-right-sizing-your-workloads.html) 

[

#### Tip #3: Monitor Database usage for deleting old databases that no longer have connections (after a snapshot)

[

#### Tip #4: Switch to an Open Source engine (MySQL, PostgreSQL)

](#tip-4:-switch-to-an-open-source-engine-\(mysql-postgresql\))

If you consider moving to an open source database engine such as MySQL or PostgreSQL, the [AWS Database Migration Service](https://aws.amazon.com/dms/)  will help you migrate your data from your source DB to your chosen target DB quickly and securely. Since this requires a heterogenous migration from two different engines, your target database requires a different schema. The [AWS Schema Conversion Tool](https://aws.amazon.com/dms/schema-conversion-tool/)  will help you generate a complete target schema, which is part of the migration process.

*   [How do I migrate my data from one DB engine to another using AWS DMS?](https://aws.amazon.com/premiumsupport/knowledge-center/migrate-db-dms/) 

[

#### Tip #5: Switch to mono AZ when relevant

](#tip-5:-switch-to-mono-az-when-relevant)

Multi-AZ deployments for the MySQL, MariaDB, Oracle, and PostgreSQL engines utilize synchronous physical replication to keep data on the standby up to date with the primary. All approaches safeguard your data in the event of a DB Instance failure or loss of an Availability Zone.

AWS recommends that you use an RDS Multi-AZ deployment as part of its [Reliability Pillar](https://docs.aws.amazon.com/wellarchitected/latest/reliability-pillar/introduction.html)  in the [Well-Architected Framework](https://aws.amazon.com/architecture/well-architected/)  as a best practice. However, you can use an RDS Single-AZ instance when reduced availability requirements and lower cost are considerations. With this understanding of RTO and RPO expectations for Single-AZ RDS instances, you can make an informed decision based on availability, risk, and costs.

For noncritical workloads like development or staging environments, multi-AZ database deployment may not be needed.

*   [Amazon RDS Under the Hood: Single-AZ instance recovery](https://aws.amazon.com/blogs/database/amazon-rds-under-the-hood-single-az-instance-recovery/) 

[

#### Tip #6: Consider replacing read replicas used for OLAP or ML by Snapshot on Amazon S3

](#tip-6:-consider-replacing-read-replicas-used-for-olap-or-ml-by-snapshot-on-amazon-s3)

You can export Amazon RDS to [Amazon S3](https://aws.amazon.com/s3/)  as [Apache Parquet](https://parquet.apache.org/) . Parquet is an efficient open columnar storage format for analytics and is up to 2x faster to export and consumes up to 6x less storage in Amazon S3, compared to other text formats. You can analyze the exported data with other AWS services such as [Amazon Athena](https://aws.amazon.com/athena/) , [Amazon EMR](https://aws.amazon.com/emr/) , and [Amazon SageMaker](https://aws.amazon.com/sagemaker/) .

You'll find instructions on getting started on the [Amazon RDS documentation](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_ExportSnapshot.html) .

[

#### Tip #7: Consider Reserved instances

](#tip-7:-consider-reserved-instances)

Using reserved DB instances, you can reserve a DB instance for a one- or three-year term. Reserved DB instances provide you with a significant discount compared to on-demand DB instance pricing. Reserved DB instances are not physical instances, but rather a billing discount applied to the use of certain on-demand DB instances in your account. Discounts for reserved DB instances are tied to instance type and AWS Region.

*   [Reserved DB instances for Amazon RDS](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_WorkingWithReservedDBInstances.html) 

[

#### Tip #8: Consider using Amazon RDS on Graviton2 Processors

](#tip-8:-consider-using-amazon-rds-on-graviton2-processors)

You can benefit from better cost performance for your Amazon Relational Database Service (RDS) databases, compared to the previous M5 and R5 generation of database instance types, with the availability of AWS Graviton2 processors for RDS.

*   [Amazon RDS on Graviton2 Processors](https://aws.amazon.com/blogs/aws/new-amazon-rds-on-graviton2-processors/) 

[

#### Tip #9: Increase your elasticity

](<#tip 9>)

Development and staging environments are typically only used for eight hours a day during the work week. You can stop these resources when they’re not in use resulting in a potential cost savings of 75% (40 hours versus 168 hours).

You can deploy the [AWS Instance Scheduler Solution](https://aws.amazon.com/solutions/implementations/instance-scheduler/) , create schedule based on business requirements and tag non-production EC2 and RDS instances to be scheduled.

![AWS Instance Scheduler](https://static.us-east-1.prod.workshops.aws/public/8844589c-f6be-4752-bd27-0dad323d1eb9/static/images/001_intro/002_core_activities/instance-scheduler.png?classes=shadow&width=500px)

This solution is [open source](https://github.com/awslabs/aws-instance-scheduler) , you can contribute to it or simply modify it to further suit it to your own requirements.

View the [implementation guide](https://docs.aws.amazon.com/solutions/latest/instance-scheduler/welcome.html)  for more details.
