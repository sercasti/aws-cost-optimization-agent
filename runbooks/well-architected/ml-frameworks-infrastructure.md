# ML Frameworks & Infrastructure

At the bottom layer of the Machine Learning stack are the frameworks, interfaces, and infrastructure for expert ML practitioners.

New algorithms are being developed all the time in different frameworks that people want to borrow from, or run in that framework – instead of having to port it themselves to a different framework. So AWS have dedicated teams for all of the major frameworks so customers have the right tool for the right job.

[

#### Tip #1: Use AWS-provided versions of your favorite framework

](#tip-1:-use-aws-provided-versions-of-your-favorite-framework)

AWS has entire teams dedicated to extracting the last bit of performance from Deep Learning libraries on AWS (read this, this, and this). One more time, do not reinvent the wheel. Please spend your time on your business differentiators.

![Faster training](https://static.us-east-1.prod.workshops.aws/public/8844589c-f6be-4752-bd27-0dad323d1eb9/static/images/002_services/003_machine_learning/030_ml_frameworks_and_infra/faster-training.gif?classes=shadow&width=500px)

In the [Faster training with optimized TensorFlow 1.6 on Amazon EC2 C5 and P3 instances](https://aws.amazon.com/blogs/machine-learning/faster-training-with-optimized-tensorflow-1-6-on-amazon-ec2-c5-and-p3-instances/)  blog post you will discover how training a [ResNet-50 benchmark](https://github.com/tensorflow/benchmarks/tree/master/scripts/tf_cnn_benchmarks)  with synthetic ImageNet dataset using AWS optimized build of TensorFlow 1.6 on a `c5.18xlarge` instance type was 7.4X faster than training on the stock TensorFlow 1.6 binaries.

To get more information on pre-configured environments to quickly build deep learning application visit [AWS Deep Learning AMIs](https://aws.amazon.com/machine-learning/amis/) .
