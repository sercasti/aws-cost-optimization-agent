# Amazon VPC

[Amazon Virtual Private Cloud (Amazon VPC)](https://aws.amazon.com/vpc/)  lets you provision a logically isolated section of the AWS Cloud where you can launch AWS resources in a virtual network that you define. You have complete control over your virtual networking environment, including selection of your own IP address range, creation of subnets, and configuration of route tables and network gateways. You can use both IPv4 and IPv6 in your VPC for secure and easy access to resources and applications.

[

#### Tip #1: Leverage VPC Endpoints instead of NAT Gateway

](#tip-1:-leverage-vpc-endpoints-instead-of-nat-gateway)

*   To access Amazon Simple Storage Service (S3)
*   To access Amazon DynamoDB

[

#### Tip #2: Check NAT Gateways costs, change architecture if possible/needed

](#tip-2:-check-nat-gateways-costs-change-architecture-if-possibleneeded)

*   In certain cases, only one NAT Gateway per VPC is required instead of one per Availability Zone (AZ)
*   In others, a dedicated NAT Gateway per AZ can reduce inter-AZ traffic

[

#### Tip #3: Analyze data transfer costs, reduce when possible

](#tip-3:-analyze-data-transfer-costs-reduce-when-possible)

*   Determine whether the instances sending the most traffic are in the same AZ as the NAT gateway
    
*   Determine whether the majority of your NAT gateway charges are from traffic to Amazon S3 or Amazon DynamoDB in the same Region
    
*   If most traffic through your NAT gateway is to AWS services that support interface VPC endpoints, then create an interface VPC endpoint for the services
    
*   If most of your internet traffic is destined to non-AWS resources, consider using an internet gateway for instances generating the highest traffic
    
*   [How can I reduce data transfer charges for my NAT gateway?](https://aws.amazon.com/premiumsupport/knowledge-center/vpc-reduce-nat-gateway-transfer-costs/) 
    
*   [Using AWS Cost Explorer to analyze data transfer costs](https://aws.amazon.com/blogs/mt/using-aws-cost-explorer-to-analyze-data-transfer-costs/) 
    
*   [Find the top contributors to traffic through the NAT gateway](https://aws.amazon.com/premiumsupport/knowledge-center/vpc-find-traffic-sources-nat-gateway/) 
    

[

#### Tip #4: Share a NAT Gateway between VPCs using Transit Gateway

](#tip-4:-share-a-nat-gateway-between-vpcs-using-transit-gateway)

NAT Gateway is a great solution to provide internet connectivity for AWS resources in private subnets. Frequently, this involves having a NAT Gateway per VPC. As the number of VPCs increases, this can result in high NAT Gateway charges due to the per-hour portion of NAT Gateway pricing.

[AWS Transit Gateway](https://aws.amazon.com/transit-gateway/)  enables attachments from/to VPCs and VPN connections in the same Region and provides the ability to route traffic between them. Each VPC or VPN attachment is associated with a single route table. The route table decides the next hop for the traffic coming from that resource attachment. A route table inside the transit gateway allows for both IPv4 or IPv6 CIDR and targets. The targets are VPCs and VPN connections.

This allows you to route traffic for the internet to a single VPC, which hosts the NAT Gateway. This enables NAT Gateway sharing, reducing per-hour connection charges.

**Example without Transit Gateway** Price per NAT gateway / hour = `$0.045/hour` (`$1.08/day` -> `$32.4/month`) `50` accounts each with `2` VPC’s with subnets in 3 AZs (`50 accounts` \* `2 VPCs` \* `3 AZs` \* `$32.4/month`) = `$9720/month`

In the diagram below, we use a Transit Gateway to share a NAT Gateway with other VPCs to enable communication with the internet for instances which are located in the private subnets.

![One NAT Gateway using Transit Gateway](https://static.us-east-1.prod.workshops.aws/public/8844589c-f6be-4752-bd27-0dad323d1eb9/static/images/002_services/005_network/003_vpc/transit_gw_nat_gw.png)

**Example with Transit Gateway** `$32.4 x 3` (3 AZ) = `$97.2/month`

_\*prices are calculated for North Virginia._

For more details please refer to the [NAT Gateway pricing](https://aws.amazon.com/vpc/pricing/#:~:text=NAT%20Gateway%20Hourly%20Charge%3A%20NAT,rate%20is%20%240.045%20per%20hour.&text=There%20was%20also%20no%20charge,zone%20using%20private%20IP%20addresses) .

[

#### Tip #5: Avoid using too many VPCs if not necessary

](#tip-5:-avoid-using-too-many-vpcs-if-not-necessary)

Avoid creating too many VPCs if not necessary and if you have resources from one VPC communicating with resources in another VPC.

Data transfer within an AWS region is between AWS services or AWS resources within the region.

Data transferred between EC2 instances or containers, or Elastic Network Interfaces across availability zones or VPC peering connections via public, private or Elastic `IPv4`, or `IPv6` addresses is charged at `$0.01` per GB for egress traffic and `$0.01` per GB for ingress traffic.

Note EC2 traffic between AZs or is effectively the same as between regions. For example, deploying a Cassandra cluster across AZs is helpful for high availability, but can hurt on network costs.
