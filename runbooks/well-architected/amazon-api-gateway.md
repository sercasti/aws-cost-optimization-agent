# Amazon API Gateway

[Amazon API Gateway](https://aws.amazon.com/api-gateway/)  is a fully managed service that makes it easy for developers to create, publish, maintain, monitor, and secure APIs at any scale. APIs act as the "front door" for applications to access data, business logic, or functionality from your backend services.

[

#### Tip #1: Consider migration from REST API to HTTP API

](#tip-1:-consider-migration-from-rest-api-to-http-api)

[HTTP APIs](https://aws.amazon.com/blogs/compute/announcing-http-apis-for-amazon-api-gateway/)  is the latest generation of managed APIs that Amazon API Gateway provides at [lower price ranges](https://aws.amazon.com/api-gateway/pricing/) .

The [Choosing between HTTP APIs and REST APIs](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-vs-rest.html)  guide will help you select the best option for your workload.

If you are using tools such as [AWS SAM](https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/serverless-getting-started.html) , switching from REST APIs to HTTP APIs might be really simple. Ex: Changing [`EvenSource`](https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/sam-property-function-eventsource.html)  `Type` from `Api` to `HttpApi`.

[

#### Tip #2: Reduce number of calls to your API implementing caching OPTIONS in the client

](#tip-2:-reduce-number-of-calls-to-your-api-implementing-caching-options-in-the-client)

When you implement your API in a [Cross-Origin Resource Sharing](https://developer.mozilla.org/de/docs/Web/HTTP/CORS) , you will have more calls to your API that the functional ones. `preflighted` requests first send an `HTTP` request by the `OPTIONS` method to the resource on the other domain, in order to determine whether the actual request is safe to send.

Before setting up an Amazon CloudFront distribution, you can implement the [`Access-Control-Max-Age`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Access-Control-Max-Age)  response header:

*   It indicates how long the results of a preflight request (that is the information contained in the `Access-Control-Allow-Methods` and `Access-Control-Allow-Headers headers`) can be cached. Firefox has a maximum of 24 hours, Chrome offers 10 minutes or 2 hours (depending on the documentation you are looking at😅).
    
*   In case of mobile application, this also limits the outbound call, further preserving battery life.
    

For example, the Serverless framework offers a [configuration option](https://www.serverless.com/framework/docs/providers/aws/events/apigateway/#enabling-cors) . This header can also be implemented in the AWS Lambda function code or through the [mapping template](https://docs.aws.amazon.com/apigateway/latest/developerguide/request-response-data-mappings.html) .
