# Machine Learning

Machine Learning is spreading across all business more than ever and it is often associated with huge spend, with budgets vanishing way faster than expected. But ML shouldn't be different than any other workloads that power your products. It can be optimized the same way and you shouldn't spend more money than necessary.

Here you'll find different tips per use case related to machine learning.

The tips will be split across the following four steps:

*   Prepare
*   Build
*   Train and Tune
*   Deploy and Manage

After the conclusion, if you haven't read it already, please refer to the "[Machine Learning](/workshops/f238037c-8f0b-446e-9c15-ebcc4908901a/en-US/002-services/003-machine-learning/-index)" section of this site. You will find dedicated tips per service.

[

#### Prepare

](#prepare)

We often see people building custom pipelines on top of Amazon EC2 or Amazon EMR reinventing the wheel and spending a lot of energy and money for the operations of data preparation step of the ML lifecycle. AWS provides several fully managed options that will help you reduce both your running cost and total cost of ownership overall. In the process you can both save money and reduce your go-to-market time.

*   [Amazon Athena](https://aws.amazon.com/athena/)  is an interactive query service that makes it easy to analyze data stored in Amazon S3 using standard SQL through a fully managed presto engine,
*   [Amazon SageMaker Processing](https://aws.amazon.com/blogs/aws/amazon-sagemaker-processing-fully-managed-data-processing-and-model-evaluation/)  is an Amazon SageMaker capability that lets you easily run your preprocessing, postprocessing and model evaluation workloads on fully managed infrastructure natively with Scikit-learn and Spark or from your custom Docker Image,
*   [AWS Glue](https://aws.amazon.com/glue)  is a fully managed extract, transform, and load (ETL) service that makes it easy to prepare and load your data for further analytics it provides a visual editor and generates python or scala scripts,
*   [AWS Lake Formation](https://aws.amazon.com/lake-formation)  is a service that helps you collect and catalogs data from databases and object storage, move the data into your new Amazon S3 data lake, clean and classify your data using machine learning algorithms, and secure access to it.

* * *

Data labeling is also a massive challenge, we see a lot of custom implementations and everyone is facing the same challenges:

*   Managing workforces
*   Reviewing
*   Accelerating data labeling
*   Reconciliation
*   Monitoring

[Amazon Sagemaker Ground Truth](https://aws.amazon.com/sagemaker/groundtruth/)  is a fully managed data labeling service that makes it easy to build highly accurate training datasets for machine learning. It provides [active learning](https://docs.aws.amazon.com/sagemaker/latest/dg/sms-automated-labeling.html) , task management, authentication and consolidation across a wide variety of data types: Images, Videos, Point Cloud Text or Custom for different use cases: classification, semantic segmentation, instances, key points, polygons, etc.

![Auto-Segmentation Tool](https://static.us-east-1.prod.workshops.aws/public/8844589c-f6be-4752-bd27-0dad323d1eb9/static/images/004_architecture/001_scenarios/004_machine_learning/smgt_autosegmentation.gif?classes=shadow&width=500px)

![3D Point Clouds](https://static.us-east-1.prod.workshops.aws/public/8844589c-f6be-4752-bd27-0dad323d1eb9/static/images/004_architecture/001_scenarios/004_machine_learning/smgt_pointcloud.gif?classes=shadow&width=500px)

You can build your own task templates, the [`amazon-sagemaker-ground-truth-task-ui`](https://github.com/aws-samples/amazon-sagemaker-ground-truth-task-uis)  github repository provides sample task UIs for Amazon SageMaker Ground Truth [custom labeling task templates](https://docs.aws.amazon.com/sagemaker/latest/dg/sms-custom-templates-step2.html) . It contains subdirectories by use case (audio, images, text, video, others).

Amazon Sagemaker Ground Truth will help you reduce labeling cost by up to 70%: not only will your data get labeled faster, labeled data will gain in quality, you will save time and money.

#### Build

](#build)

[Amazon SageMaker Notebook Instances](https://docs.aws.amazon.com/sagemaker/latest/dg/nbi.html)  and [Amazon SageMaker Studio](https://docs.aws.amazon.com/sagemaker/latest/dg/gs-studio.html)  are great tools for you to build explore and build your models.

Amazon SageMaker is an open tool kit which aims at simplifying Machine Learning development lifecycle. It is open because you can use each of the Amazon SageMaker feature independently, you can explore in Notebook instances and train locally, you can explore locally and train in Amazon SageMaker, you can train locally and deploy on Amazon SageMaker.

When you start building your own algorithm, if your compliance constraints allow you to download data on local machine, you can do so and move to the Amazon SageMaker more secure environment when you can't hold and process your data locally anymore.

Please see "[Machine Learning](/workshops/f238037c-8f0b-446e-9c15-ebcc4908901a/en-US/002-services/003-machine-learning/-index)" section of this site for more details.

[

#### Train and Tune

](#train-and-tune)

A common anti-pattern we are seeing is people running their training jobs manually on SageMaker Notebook instances with large instance types and forget about it wasting a lot of idle compute hours.

Moving to the [Amazon SageMaker training API](https://docs.aws.amazon.com/sagemaker/latest/dg/how-it-works-training.html)  will be a more beneficial move for both your scalability and wallet.

* * *

Another large part of the training and tuning phase is figuring out the right set of hyper parameters for a machine learning model. We often see craftsmanship in that space and it can be quite expensive not to mention that this often involves training hundreds of different models.

You can save (a lot of) money by using [automatic hyperparameter tuning](https://docs.aws.amazon.com/sagemaker/latest/dg/automatic-model-tuning.html)  in Amazon SageMaker. It can quickly and efficiently figures out the optimal set of parameters with a limited amount of training jobs. You define the metrics, you define the hyperparameters (a model can be an hyperparameter).

[Hyperparameter Tuning Job](https://docs.aws.amazon.com/sagemaker/latest/dg/automatic-model-tuning-ex.html)  example.

* * *

More advanced technic such as [model pruning](https://github.com/aws/amazon-sagemaker-examples/blob/master/sagemaker-debugger/pytorch_iterative_model_pruning/iterative_model_pruning_alexnet.ipynb)  will help you enhance your model size while maintaining performance.

The following gif animation shows the number of parameters per layer for each pruning iteration. You can see that most of the parameters are pruned in the last convolutional layers. The model starts with 57 million parameters and a size of 218 MB. After 10 iterations it consists of only 18 million parameters and 70 MB. Fewer parameters mean smaller model size, and hence, faster training and inference.

![Pruning Results for AlexNet](https://static.us-east-1.prod.workshops.aws/public/8844589c-f6be-4752-bd27-0dad323d1eb9/static/images/004_architecture/001_scenarios/004_machine_learning/pruning_results_alexnet.gif?classes=shadow&width=500px)

#### Deploy and Manage

](#deploy-and-manage)

Everything that will reduce your total cost of ownership is great to look at. In the case of deploy of your model, [Amazon SageMaker](https://docs.aws.amazon.com/sagemaker/latest/dg/how-it-works-deployment.html)  will provide scalable and secure execution environment.

If you are in a kubernetes environment, you can also leverage Amazon SageMaker with the [SageMaker operators for Kubernetes](https://docs.aws.amazon.com/sagemaker/latest/dg/amazon-sagemaker-operators-for-kubernetes.html) .

The blog post [Simplify Machine Learning Inference on Kubernetes with Amazon SageMaker Operators](https://aws.amazon.com/blogs/machine-learning/simplify-machine-learning-inference-on-kubernetes-with-amazon-sagemaker-operators/)  describes how to deploy real-time endpoint models.

[

#### Conclusion

](#conclusion)

You may also review the blog post [Lowering total cost of ownership for machine learning and increasing productivity with Amazon SageMaker](https://aws.amazon.com/blogs/machine-learning/lowering-total-cost-of-ownership-for-machine-learning-and-increasing-productivity-with-amazon-sagemaker/) . It provides a Total Cost of Ownership (TCO) analysis of ML costs with [Amazon SageMaker](https://aws.amazon.com/sagemaker/)  - a fully managed service to support the entire ML models lifecycle - compared to other cloud-based ML options such as self-managed [Amazon EC2](https://aws.amazon.com/ec2)  and AWS managed [Amazon EKS](https://aws.amazon.com/ec2) . The findings show that the TCO over a three-year horizon is 54% lower.
